## 3. scheduling-kit today (at origin/main 0.8.0)

**Shape**: ESM lib, exports `.`/`components`/`adapters`/`payments(/types)`/`core`/`lib`/
`onboarding`/`reconciliation`/`stores`/`testing`. Deps: effect ^3.19.14, zod ^4.3.5,
drizzle-orm 0.39.3; auth-pg now optional peer (legacy dynamic-import fallback only).

**Good bones**:
- `SchedulingAdapter` contract: **17 Effect-typed methods** (services, providers, dates/slots,
  checkSlotAvailability, softHoldSlot/releaseSoftHold, createBooking(+WithPaymentRef),
  get/cancel/reschedule, clients). `SchedulingResult<A> = Effect<A, SchedulingError>`.
- `completeBookingWithAltPayment` saga with compensation (release-on-payment-failure,
  refund+release-on-booking-failure).
- PaymentAdapter contract + Stripe/Venmo(PayPal)/manual implementations; PaymentCapabilities
  with type-level `cash: false`; onboarding ports (CredentialStore/EncryptionProvider).
- HomegrownAdapter (751 LOC) over injected business-pg schemas + `withDb` tenant pinning;
  pure availability-engine; cassette record/replay tooling (no cassettes committed — pairs with
  the planned fresh dev Acuity/GlossGenius accounts).
- 12 Svelte 5 components + runes checkout store.

**Verified-current gaps (re-checked at 0.8.0, not the stale 0.7.2 critique)**:
- **Idempotency dedup never wired**: `createBooking` writes `idempotencyKey` with no lookup /
  onConflict; `withIdempotency` util exists unused. Check-then-book race; holds are advisory.
- **Error collapse**: HomegrownAdapter `fromAsync` maps everything to
  `InfrastructureError('UNKNOWN')` — not-found etc. never typed.
- **Vendor-coupled error taxonomy**: `AcuityError|CalComError` baked into core union.
- **MassageIthaca branding in the published package**: `MI-` confirmation codes
  (availability-engine), `massageithaca.com` / `jen@massageithaca.com` / Danby Rd defaults in
  components, `defaultPractitionerHandle='jen'`.
- **No server runtime**: no HTTP host, webhook receiver, jobs/queues (hold expiry,
  reconciliation sweeps), notifications (email/SMS/reminders), calendar sync, admin UI.
- **No multi-tenant domain model** (tenancy only via injected `withDb` closure — by design so
  far), no org/tenant types.
- **No parity surface**: intake forms, SOAP notes, packages/gift certs/memberships,
  classes/group ("managed-registration" is named in the instance-model contract, absent in kit),
  recurring appts, coupons, no-show fees, HIPAA-ish audit/records.
- CalCom adapter 100% stub; reconciliation module Acuity-named; kit ships reconciliation *types*
  while the Redis store impl lives app-side in MassageIthaca.
- `cancelBookingWithRefund` regex-parses processor/txn out of `paymentRef` notes (fragile).
- Bazel: `.bazelrc` points at tinyland-inc/bazel-registry, but MODULE.bazel has **zero tinyland
  bazel_deps** (auth-pg edge deliberately removed at 0.7.8). Kit/bridge have not joined the
  module graph the way tinyland-schemas/caldav-client already did (Bzlmod dep, npm edge retired).

## 4. scheduling-bridge today

**Shape**: HTTP bridge server (`src/server/handler.ts`, **2,754-line monolith**) + async job
queue + snapshot cache + Playwright automation, K8s-forward (Modal legacy, TIN-981). Exports
`.`/`./server`; deps kit ^0.8.0, effect, playwright-core, ioredis, pg, prom-client. Bazel module
depends on kit 0.8.0 + tinyland_auth 0.3.0. Build = Bazel `//:pkg` artifact truth.

**Endpoints**: /metrics /ready /health, GET /services, POST /availability/{dates,slots,check,
refresh}, GET /availability/snapshot(+canary), /internal/availability/{heartbeat,readiness,
wait-ready}, /jobs/:id, POST /booking/create, /booking/jobs (create-with-payment is 410
ASYNC_REQUIRED). Snapshot-first reads; Redis SETNX single-flight (the paper's O(1) primitive).

**Salvage map for the DAG vision** (already monadic, keep):
- Step programs in `src/adapters/acuity/steps/` are Kleisli arrows
  `(params) => Effect<Result, MiddlewareError, BrowserService>`: navigate, fillFormFields,
  bypassPayment/coupon, submit, extractConfirmation, read dates/slots (+ direct `?appointmentType`
  URL reads), extract-business, slot-read-profile.
- The `acuitySteps` table in handler.ts is literally a flat registry of future DAG nodes.
- **Fuzzy-in**: `ServiceResolver` Context.Tag with confidence-scored 4-strategy cascade
  (id 1.0 → normalized 0.95 → token 0.5-0.9 → Levenshtein 0.3-0.7).
- **Fuzzy-out**: `NavigateResult.landingStep` (observe where the wizard actually landed).
- Selector registry with fallback chains + probe/healthCheck (affordance layer).
- `BridgeJobCommand`/`BridgeJobRecord` discriminated-union command algebra + durable stores
  (memory/Redis/Postgres) — natural substrate for DAG-node execution state.
- Snapshot freshness semantics (observedAt/staleAt/expiresAt) = node-output freshness.
- Remote adapter proves the 17-method interface composes across process boundaries.

**Gaps to the vision**:
- Zero reified DAG/flow/graph types; sequencing is imperative `Effect.gen` per flow; no
  plan-vs-execute separation, no introspection/replay, no per-step checkpoint/resume (job kinds
  are coarse: whole booking = 1 job).
- Flow concepts (date picking, intake, SOAP, payment panels) exist only as Acuity steps;
  selectors carry MassageIthaca tenant leakage (intake field ids, "referral from Noha…").
- Acuity-only despite adapter-hub framing; getBooking/cancel/reschedule NOT_IMPLEMENTED;
  providers stubbed; soft holds unsupported.
- handler.ts monolith conflates routing/validation/cache/readiness — the seam to split when the
  DAG layer lands.
- Paper vision split across `docs/paper.md` (anti-corruption-layer / strangler-fig, **ASE 2026
  Industry Showcase abstract due 2026-06-23**, bridge issue #10) and
  `docs/paper/acuity-middleware-paper.tex` (O(1) cache-coherent scraping; evaluation TODOs await
  Phase 1.1 bake data — `paper/data/phase1/` and `bench/results/` are empty).
- Stranded local-only branches per bridge#47: feat/k8s-phase1-bench, feat/phase1.1-paper,
  feat/k8s-phase1-parity, feat/k8s-phase1-docker-ghcr (no PRs). GHCR image still named
  `acuity-middleware`.
